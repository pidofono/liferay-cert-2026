## Environment

- **Product version:** `dxp-2026.q1.0-lts` (Quarterly Release — use modern patterns)
- **Target platform:** `2026.q1.0`
- **Default environment:** `dev` (prefer `local` for fresh development)
- **JVM:** JDK 21 (switch with `. scripts/jdk.sh 21`)

Because this is a Q-release (>= 7.4), **prefer Client Extensions, Fragments, and Objects** over traditional OSGi modules. Only use OSGi modules when Client Extensions cannot fulfill requirements.

## Common Commands

```bash
# Server lifecycle
blade server init          # Download Liferay bundle into /bundles
blade server start         # Start server (background)
blade server start -t      # Start and tail logs
blade server start -d      # Start in debug mode (port 8000)

# Build & deploy
blade gw deploy            # Build and deploy all modules/client-extensions
blade gw tasks             # List all available Gradle tasks

# Remote deployment helpers (target: pi@192.168.1.43)
scripts/deploy-module.sh <module-name>   # Build + SCP a single OSGi module
scripts/deploy-configs.sh <env>          # Push configs/{env} to remote server
scripts/deploy-remote.sh                 # Tail remote catalina.out via SSH
scripts/tail-logs.sh                     # (alias for log tailing)

# Logs (local)
tail -f bundles/tomcat/logs/catalina.out
```


## Existing Module: `ai-cert`

A Liferay REST Builder module that exposes an AI Q&A API (`/o/ai-cert/v1.0/ask`).

- **API surface:** `POST /ask` — takes `{"question": "..."}`, returns `{"answer": "..."}` (proxies OpenAI `gpt-4.1-mini`)
- **REST contract:** `modules/ai-cert/ai-cert-impl/rest-openapi.yaml` — edit this to add/change endpoints, then run REST Builder to regenerate boilerplate
- **Implementation entry point:** `AiAskResponseResourceImpl.java` — the only non-generated file to extend
- **Base URI:** `/ai-cert` (configured in `rest-config.yaml`)

### REST Builder regeneration

After modifying `rest-openapi.yaml`:

```bash
blade gw buildREST   # regenerates api/client/impl boilerplate; only *Impl.java is preserved
```

## Rules & AI Configuration

AI rules are stored in `.workspace-rules/` and symlinked into each tool's config folder (`.claude/`, `.cursor/rules/`, `.gemini/`, `.windsurf/rules/`, `.github/`). Add new rule files there and symlink them — do not write rules directly into tool-specific folders.
